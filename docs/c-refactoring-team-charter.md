# C 경계 분리 팀장 — 고정 목표 및 인수 계약

요청일: 2026-09-29. 팀장 모델: GPT-5.6 Luna.
보고 대상: Codex 스레드 `01a0ea6b-f59e-7c60-a6a2-bd7f0adeb738`
(유지보수성과 프로토콜 확장성 개선).

## 고정 목표

Rust 게이트웨이로 점진 이전할 수 있도록 현재 C 구현의 최소 경계를 추출한다.
FreeRDP 세션, 에이전트 통신, 장치/사용자 세션, 입력 변환, 영상 수신/처리의
책임과 수명을 분리하고, 기존 wire/CLI/장치 동작을 유지한다.
실제 코드 변경, 회귀 검증, 원본 Windows PC를 이용한 입력 검증 및 전후 영상
계측까지 끝내고 이 요청 스레드로 증거와 결과를 보고한다.

전체 C 재작성, Rust 포팅, Web/VNC 신규 기능 구현은 이번 목표에 포함하지 않는다.
향후 포팅을 위해 필요한 인터페이스만 만든다. 세부 순서는 기존 리팩토링안의
단계 0~3을 참고하되 불필요한 중간 추상화를 만들지 않는다.

## 인수 조건 — 모두 필수

1. 한국어 입력: 실제 원본 Windows의 텍스트 입력란에서 한글 문장, 받침/쌍자음,
   한영 전환, 공백·문장부호·수정이 기대 문자열과 일치해야 한다.
2. 조합기(IME) 입력: 조합 중 Backspace, 조합 확정, 커서 이동, 포커스 이동 후
   재입력, 한영 전환과 수정키 해제, 필요 시 후보 선택을 확인한다.
   중복·누락·조합 취소 오류·키 고착이 없어야 한다. 지원 경로(물리 scan code/
   Unicode text)를 구분하며 미지원 기능을 기존 지원 기능처럼 주장하지 않는다.
3. 영어 입력: 대소문자, Shift/Caps Lock, 숫자·기호, 연속 타이핑, Backspace,
   Ctrl 조합 및 반복 연결 뒤 입력이 기대값과 일치해야 한다.
4. 영상: 동일 장치·프로토콜·해상도·화질·부하 조건에서 리팩토링 이전과 동일하거나
   개선되어야 한다. 지연 p50/p95, FPS·정지 및 마지막 프레임 전달을 비교한다.
   오차·조건 차이로 판정이 어려우면 미완료/판정 보류이며 자동 합격하지 않는다.

각 입력 시나리오의 정확한 기대 문자열과 조작 순서를 구현 전에 고정하고,
변경 전후 동일하게 실행한다. clipboard 붙여넣기 성공을 실제 타이핑/IME 검증으로
대체하지 않는다. 자동 단위 테스트만으로 원격 입력 실측을 대체하지 않는다.
테스트용 문서에서 검증하고 기존 사용자 문서는 변경하지 않는다.

## 실행 원칙

- 시작 시 `create_goal`로 위 목표와 네 가지 인수 조건을 등록한다. 예산은 지정하지 않는다.
- 팀장은 조율·경계 계약·결과 검토를 맡고 구현/QA/리뷰는 필요에 따라 sub-agent에 위임한다.
  새 사용자용 스레드를 추가 생성하지 않는다. 팀장은 GPT-5.6 Luna를 유지한다.
- 기존 변경 README.md, deploy/S100nanokvm-agent, src/agent.c 및 문서·계측 도구를
  보존한다. 같은 디렉터리의 다른 작업 변경을 되돌리지 않는다. 담당 파일을 명시해
  충돌을 피하고 기존 변경과 이번 diff를 구분한다.
- 먼저 기존 작업과 실행물·환경을 식별하고 기준선을 확보한다. 새 코드 배포 전에
  기존 바이너리/설정으로 돌아갈 경로를 마련한다. 공유 장치에서 중복 세션을 만들지 않는다.
- 필요한 빌드·테스트·통제된 실장치 검증을 수행한다. 영구 배포·인프라 변경·무관한
  서비스 변경을 별도 목표로 확대하지 않는다. 장치 접근이나 권한이 막히면 정확한
  차단 원인과 필요한 사용자 동작을 보고하고 가능한 독립 작업은 계속한다.
- 한국어/IME/영어 및 전후 계측이 실제 검증되지 않았으면 완료로 표시하지 않는다.

시작했으므로 새 스레드에서는 해당 session ID에 의존하지 말고 실제 가용성을 확인한다.

오류 0x4도 있었지만 마지막 재접속/영상 계측은 성공했다.

## 결과 보고

사용자는 팀장 스레드가 이 요청 스레드에 결과를 보내는 협업 흐름을 명시적으로
승인했다. 완료 후 `send_message_to_thread`로 보고 대상 ID에 최종 보고를 전송한다.
전달 실패 시 팀장 스레드에 실패 사실과 최종 보고 파일을 남긴다.
중요 차단이나 필수 사용자 개입도 같은 대상에 보고하되 변경 없는 상태 보고는 반복하지 않는다.

최종 보고에는 변경 파일/경계, 테스트 결과, 네 인수 조건 각각의 PASS/FAIL/미검증,
실제 입력 증거, 변경 전후 실행물 식별자·계측 CSV/JSON·오차·비교 판단,
남은 제한 및 복구 방법을 포함한다. 모든 조건을 충족한 뒤 goal을 complete로 표시한다.
